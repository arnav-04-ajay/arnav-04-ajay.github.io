Project Overview

Displaying directions and other driving stats in a car is pretty common these days, whether that's in the form of phone holders or integrated displays made by the manufacturer. It's less common to see this done on bikes in a way that isn't obstructive and doesn't interfere with normal riding. Thus, we wanted to make a heads-up display integrated into a helmet for directions and other riding stats.

Project Goals

Strong Use Case

Want the display to feature maps with routing, time, speed, and other helpful stats for the rider.

Compact / Unobtrusive

The device shall not obstruct the user's riding experience in any way, and will keep a low profile.

Ease of Use

Device should be easy to 'plug-and-play' (as shown in the demo at the end of this page)

Circuitry and Overall System

The device itself operates based on 4 main components:

  • An ESP32-S3 (Heltec WiFi LoRa 32) is used as the main MCU. It's used for interacting with the onboard I/O components, hosting its own webserver, and using GET requests from the Google Maps API to service route and direction data to the user, store and sync user ride data locally and to the cloud, and display all data in a clean manner on a display
  • A 128x64 OLED display is used to display all data in a dashboard-style which will be described later. The physical construction of the display to create the HUD effect will also be described in later sections
  • An onboard GPS and accelerometer are used for live route and ride statistics that are stored on an SD card during the ride (before it is eventually synced to the cloud)
  • 3 pushbuttons are included in the circuit and exposed to the user to indicate ride start/stop and to sync ride data to the cloud

In-built Display and Web Interface

All data for a particular ride (once the user starts the ride) is stored locally to an SD card. Once the user stops the ride and decides to sync the data, it is sent to an AWS-hosted Flask based server where all previous rides can be visualized (as seen by the first image). Additionally, during the ride the user can see the following (and can be seen in the second and third images):

  • A monochrome version of a google maps feed centered around the current location with route guidance to a pre-programmed destination
  • Current time in the top right of the display
  • Current speed in the top left of the display (in km/hr)
  • Current incline at the bottom of the display (useful for mountain biking or other applications with variable terrain)

Physical Design

The physical design itself is quite involved to make sure the whole system fits neatly on a bike helmet while also making it easy for users to interact with. All controls electronics including the GPS, MCU, IMU, and SD card reader along with the 3 user-interactable push buttons are located in a custom-designed enclosure on the back of the helmet. The full enclosure is relatively lightweight and it's presence is not felt when wearing the helmet. The display is located at the front of the helmet with a thin, non-exposed wire running between it and the control enclosure across the inside of the helmet. The display is constructed as follows:

  • A 128x64 pixel OLED display is placed lengthwise parallel to the user's line of sight (and thus the user cannot see the display directly)
  • A beamsplitter glass is placed at a 60 degree angle with respect to the OLED display in front of the user's line of sight. This allows the user to see the reflection of the display on the glass while also being able to look straight forward, giving the HUD effect
  • A lens is placed after the OLED display (in between the display and the beamsplitter) allowing the user's vision to be able to focus correctly on the display's refleciton on the beamsplitter (and not appear blurry)
